Starting it

Do thisWhat happens
start.cmdServes localhost:7457 and opens your browser. The server window opens minimised — it lives in the taskbar as Control Tower. Run it again while it is already up and it just opens the page.
start-phone.cmdSame, but reachable from your phone on this Wi-Fi. Prints an access code — it does not minimise, because you need to read that code.
Close the server windowStops the server. There is no stop button in the page.
Restart it with the page openFine. The write token belongs to one server run, so the page quietly picks up the new one and retries — it used to fail every write with bad token until you reloaded.

Nothing is installed and nothing leaves the machine. The server binds to 127.0.0.1 unless you deliberately start it in phone mode.

What each status means

Status is inferred. Permission prompts and idle-waiting are never written to a transcript, so this is a well-informed guess, not a reading.

StatusWhat it is telling you
workingA tool call is in flight, or Claude is mid-turn.
waiting for youClaude handed back within the last 10 minutes. You are probably still in the loop.
needs youA quick tool call (an edit, a write) has been pending too long, so it is probably sitting on a permission prompt.
still runningA long Bash, subagent or MCP call. Not waiting on you, and deliberately out of the attention queue — a five-minute test run used to announce itself as needing you.
doneFinished its turn more than 10 minutes ago with nothing pending. Out of the queue.
idleQuiet for hours, or marked idle by you.
in this pageA chat with no terminal behind it. Open it and carry on.
endedNo live process. Still resumable from history.

Two things keep the guess honest: slow tools get two minutes of patience before they even become still running, and a session in auto, acceptEdits, bypassPermissions, dontAsk or plan mode is never called blocked — it has no prompt to be waiting on.

Where a chat came from

Every card carries a chip saying where that session began. Claude Code stamps each transcript row with an entrypoint, so this is read, not guessed.

ChipMeans
terminalStarted with claude on a command line.
VS CodeStarted from the VS Code extension.
Claude appStarted from the Claude desktop app.
claude.aiStarted from the web.
this pageStarted here, headless. There is no terminal behind it.
unknownNothing in the transcript says.

A session can begin in one place and be continued in another. The chip is where it started; a separate N turns here chip counts the messages you have sent it from this dashboard. Group the board by where it started to see the split.

Chatting in the page

+ New chat starts a conversation that happens right here. Pick a folder, type, Ctrl+Enter. The answer streams in, tool calls appear as chips, and the panel reloads the saved transcript when the turn ends. Replying from a card does the same thing and opens the panel so you can watch. 

claude -p "<your message>" --verbose --output-format stream-json --include-partial-messages \
  [--resume <id> | --session-id <new uuid>] [--model …] [--effort …]

What it is allowed to touch

Print mode has no way to ask you about a tool call — there is no permission-prompt hook in this CLI — so it has to be agreed before the turn starts. That is the can selector.

StanceWhat it passes
read only (default)--allowedTools Read Grep Glob NotebookRead WebFetch WebSearch TodoWrite Skill — nothing can be written, so nothing needs asking.
read + edit files--permission-mode acceptEdits — file edits go through without asking.
anything, no prompts--permission-mode bypassPermissions. Refused for anything but this machine — a paired phone cannot select it.

Claude Code cannot retune a session that is already running, so changing model or effort opens a new window on the same history. Whatever window is already running it keeps its own settings.

Providers

Claude Code is the first entry in a small registry (GET /api/providers), and OpenAI is the second. They work differently and the board says so rather than pretending otherwise: OpenAI has no local process to watch and no terminal to resume in — every chat with it exists only because this app called the API and kept the reply.

Set it up⋯ menu → OpenAI API key — set it up. Get one at platform.openai.com/api-keys — billed separately from any ChatGPT subscription.
Where the key livesprovider-keys.json next to the server, plaintext — same trust model as an MCP server's own env values. GET /api/provider-keys only ever reports whether one is set and its last 4 characters, never the key itself.
Starting a chatPick ChatGPT from the assistant dropdown in + New chat. No folder, no permission stance — neither means anything without something running locally.
Forget vs. DeleteA Claude transcript lives on its own regardless of this app, so forget just unpins the card. An OpenAI chat's file is the only copy — forget only unpins it too (it sinks into history), Delete removes it for good.

A local-CLI agent with its own on-disk transcripts (a hypothetical Codex CLI, Gemini CLI, …) could get the same full parity Claude has. Nothing like that is wired up — none was installed on this machine to build and test against.

Editing rules, skills and MCP servers

Every row that belongs to you has edit, every section a + new …, permission rules an × each, and any editable file a history. Text files open in an editor (Ctrl+Enter saves). MCP servers and hooks open as forms, so a typo cannot corrupt anything.

Guard railWhy
The page can only name a file the server already publishedAn absolute path or a ../ traversal is refused outright.
Marketplace plugin copies are read-onlyAn edit there is erased by the next plugin update, so it is not offered.
New files get their path built server-sideFrom a validated name plus a known scope, never from what the page sends.
Every write and delete copies the original to trash/Nothing is unrecoverable. history reads that folder back, with view and restore. Capped at 200 versions.
Writes are atomic and JSON is re-parsed off disk before the rename~/.claude.json also holds your account and every project record. Only its mcpServers key is ever touched, and deleting that file is refused.
Adding an allow rule asks you to confirmIt means Claude stops asking about that thing from then on.

A new or changed MCP server is picked up by the next Claude session, not a running one.

Your phone

start-phone.cmd opens the port to your local network and prints a pairing link with an access code. Open it once on the phone and that device is remembered by cookie for thirty days.

The easy way across is the pairing page — ⋯ → Phone access on the board, or /pair straight in. It draws a QR code for each network address with the access code already in the link, so there is nothing to type on the phone: point the camera at it and tap. If the port is not open, that page says so and says what to run instead.

What is enforcedHow
No code, no entryAn unlock screen for pages, a 401 for API calls. Eight wrong guesses locks that device out for ten minutes.
Judged by the socketNot by a Host header a client can invent. Requests from this machine never need the code.
The no-prompts stance is refusedA paired phone cannot run tools unasked.
Your layer travelsSections, theme, collapsed groups, dismissals live in prefs.json on the server, so the phone sees the same dashboard.

Understand what you are opening: this page launches terminals on your PC. Your own Wi-Fi only, never port-forwarded, and not on café networks. It is plain HTTP, so the code crosses the LAN unencrypted.

The API

Loopback JSON, no dependencies. Reads are plain GETs; anything that writes needs the per-run token the page is given, so a random website cannot drive your terminal through this port.

Reads
GET /api/stateEvery session, its status, chips and queue position.
GET /api/eventsServer-sent stream of the above, pushed when anything changes.
GET /api/transcript?id=&limit=A conversation. Limit clamped to 600.
GET /api/image?id=&uuid=&b=One image out of a transcript, by row and block.
GET /api/search?q=Full-text across every transcript.
GET /api/export?id=A conversation as Markdown, as a download.
GET /api/toolboxMCP servers, skills, agents, commands, and the rules inventory.
GET /api/usageTokens per day, model, project and session, plus the rate-limit window.
GET /api/prefs · GET /api/trashYour settings; the version history.
GET /api/tokenThe current write token, so a page open across a restart can recover. A cross-origin page can call it but cannot read the answer, which is what makes the token worth having.
GET /api/providersThe provider registry — what each one can do, and whether it's configured.
GET /api/provider-keysWhether a key is set per provider, and its last 4 characters. Never the key itself.
Writes
POST /api/chat · /chat/stop · /chat/forget · /chat/deleteStart a turn (any provider), kill one, stop pinning a chat, delete an OpenAI chat's file for good.
GET /api/chat/events?run=That run's event stream, replayed from the start for late joiners.
POST /api/reply · /new-terminalOpen a terminal on an existing or new Claude chat.
POST /api/provider-keys · /delete · /testSave, remove or test a provider's API key.
POST /api/file/read · write · create · deleteThe editor. Only files the inventory published.
POST /api/mcp/save · /mcp/deleteStructured MCP edits.
POST /api/permission · /api/hookAdd or remove a permission rule or a hook.
POST /api/trash/read · restore · emptyThe version history.
POST /api/prefs · /api/idle · /api/openSettings, idle marks, open a file or folder locally.

What it cannot do

LimitWhy
An in-page chat cannot ask you about a tool callPrint mode has no permission-prompt hook. Agree a stance up front, or use a terminal.
Status is a guessPrompts and idle-waiting are never logged. A long build can still look like a stalled prompt, which is why mark idle exists.
No cost figuresNothing on disk records one on this plan — every request reports zero. The totals are wired up and would work if that changed.
Only Claude Code sessions on this machine, plus OpenAI chats this app itself startedclaude.ai's own web chats live server-side and are not in ~/.claude; nothing watches ChatGPT the way it watches Claude Code, because there's nothing local to watch.
Plan quota is not shown as a barOnly the window the API reports, and only after one in-page turn. Run /usage in Claude Code for Anthropic's own breakdown.

Tests

node test/run.mjs            # everything
node test/run.mjs guards     # only suites matching "guards"

It starts its own server on 7999 with FLEET_DRY_RUN=1, so nothing in the suite can open a terminal, and points prefs at a scratch file so a run never rearranges your dashboard. 106 checks: the write refusals, the response shapes each panel assumes, and a browser pass over the board, the Enter rule, the counts, card expansion, accessible names, focus trapping and deep search. test/api-guards.mjs is the one to keep green.
